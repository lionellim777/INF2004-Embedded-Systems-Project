# Barcode: 10-bit millisecond widths, value code and IR fault bit

Owner: Jing Hai (Buddy 3). Host tests and build only; nothing flashed or run on
the car.

## Changes

- `barcode_runs.h`: each of the 29 bar/space widths is stored in 10 bits at
  1 ms steps (rounded to nearest). Previously 20 bits at 1 µs.
  The get/set interface is unchanged: callers still pass and receive µs (or
  distance units), so no other module changed. Timestamps and decoder
  arithmetic stay 32-bit. The 750 ms limit is 750 steps, which fits 10 bits.
- `navigation_commands.h/.c`: 3-bit barcode value
  `0 none, 1-4 A-D, 5 other letter (E-Z), 6 unreadable, 7 spare`.
  Printed as `value=` in `[BARCODE EVENT]` and `[BARCODE RETRY]` log lines.
- `ir_fault.h`: IR fault is bit 6 (`0x40`) of the shared fault mask. It is set
  when the existing `integrity_fault` flag is set (sample gap above 3 ms, edge
  buffer overflow or event queue overflow). Printed as `ir_fault=` in
  `[BARCODE RETRY]`.

## Is 1 ms precise enough?

- Course speed is 600 counts/s per wheel, about 44 mm/s (60 mm wheel, 2543
  counts/rev). A 3 mm narrow bar then lasts about 68 ms, so rounding to 1 ms is
  at most 0.5 ms, under 1% per bar.
- At the agreed limit of 150 mm/s a narrow bar lasts 20 ms (2.5%). The fastest
  existing optical test uses 15 ms bars (3.3%).
- Evidence from the host suites with 10-bit storage:
  - All 10 recorded captures from real runs (v5.10, v5.11 and v5.30 logs)
    still decode to the same letter, in both directions, from packed storage.
  - Independent optical A-Z at 15/30/60 ms, filtered low-contrast half-A
    reconstructions, distance-mode captures and continuous scans all pass.
  - New worst-case check: every narrow bar rounded up and every wide bar
    rounded down by 499 µs, at 15 ms and 68 ms narrow, for A-Z in both
    directions: all 104 decode correctly.
- Synthetic tests that used sub-millisecond widths (100/300 µs) now treat
  those numbers as milliseconds. Every decoder accept/reject expectation is
  unchanged.

## Known effects and open items

- The stationary hand-scan build uses 8 µs ticks, so its stored resolution
  becomes 8 ms. Its test cannot confirm this until the timer assertion above
  is fixed.
- `docs/data-budget/minimum-bit-budget.md` (generated by `tools/bit_budget.py`)
  still lists 20-bit µs widths and a 5-bit barcode value. It needs
  regenerating if the team keeps these changes.
- The 3-bit value cannot tell Y from Z (both are 5). The robot still acts on
  the actual letter; only telemetry is affected.
- Not done: the `on_hump` signal for line loss over humps needs Buddy 4's
  terrain output first.
